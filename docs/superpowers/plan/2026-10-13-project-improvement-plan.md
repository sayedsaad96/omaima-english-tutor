## 1. المرجع والنطاق

المشروع الحالي موقع تسويقي ثنائي اللغة باستخدام Next.js 16.3.5 وReact 19.2.8، مع TypeScript وTailwind CSS وZod. الحجز يُجهّز رسالة واتساب، والاختبار يُصحح محليًا. هذه الخطة تحافظ على هذا النطاق: لا حسابات طلاب أو مدفوعات أو قاعدة بيانات متعلمين في دورة التنفيذ الحالية.

اعتماد المستخدم لهذه الخطة هو طلب إنشائها، وليس إثباتًا لتنفيذها أو نشرها. عند بدء التنفيذ تُحدّث حالات المهام والدليل العملي لكل مهمة.

## 2. قواعد التنفيذ ومعنى اكتمال المهمة

- تنفّذ كل مهمة في تغيير محدود قابل للمراجعة، مع اختبار السلوك المتأثر عندما يكون الاختبار ذا قيمة.
- إصلاح السلوك لا يُخلط بإعادة تصميم واسعة. التحسين البصري البسيط يكفيه فحص بصري مناسب.
- تستخدم قواعد Zod القائمة بدل تكرار قواعد التحقق في الواجهة؛ لا تُضاف مكتبة لأمر تغطيه الأدوات الحالية.
- تبقى بيانات الاسم والهاتف في ذاكرة النموذج؛ لا تدخل روابط الموقع أو التحليلات أو سجلات الأخطاء أو ملفات الاختبار المحفوظة ببيانات حقيقية.
- تستخدم بيانات اتصال وهمية في التحقق الآلي. لا ترسل الاختبارات رسائل فعلية ولا تؤكد مواعيد خارجية.
- تحديث العربية والإنجليزية وأنواع القاموس والتوثيق جزء من المهمة التي تغيّرها.
- لا تُحذف الملفات غير المتتبعة الموجودة مسبقًا، ولا تُضمّ تلقائيًا إلى تغييرات الخطة.
- تعني «مكتملة»: تحقق معيار القبول، ونجاح الفحوص المناسبة، ومراجعة التغيير، وتحديث التوثيق المتأثر. وجود الكود وحده لا يكفي.
- لا يبدأ تنفيذ المرحلة التالية قبل اجتياز بوابة المرحلة السابقة. يجوز تجهيز الصور والمحتوى بالتوازي دون تعديل التطبيق.

**المخاطرة:** التنقل بين جذور تخطيط مختلفة قد يحمّل وثيقة كاملة وفق دليل Next.js. يُختبر تبديل اللغة والثيم، ولا يُفترض احتفاظ النموذج بحالته عبر تبديل اللغة. إذا تغيّر هذا السلوك تُوثّق النتيجة قبل الدمج.

### أوامر التحقق الحالية

تُنفذ بالتتابع بحسب الاعتماديات من جذر المشروع. يسبق بناء الإنتاج اختبار المتصفح؛ يجب إيقاف أي خادم قديم قبل اختبار البناء الجديد، لأن Playwright المحلي يسمح بإعادة استخدام الخادم.

```powershell
npm run lint
npm run typecheck
npm test
$env:NEXT_PUBLIC_SITE_URL = 'http://127.0.0.1:3000'
$env:NEXT_PUBLIC_WHATSAPP_NUMBER = '201111111111'
npm run build
npm run test:e2e
```

أوامر بديلة جُرّبت في المراجعة السابقة للتشخيص فقط، ولا تحل محل التحقق من الإعداد الرسمي:

```powershell
npm test -- --pool=threads --maxWorkers=1 --no-file-parallelism
npm run build -- --webpack
npm run test:e2e -- --workers=2
```

المتغيرات أعلاه للاختبار المحلي فقط. لا تستخدمها للنشر الحقيقي، ولا تستخدم عملية shell نفسها لبناء الإنتاج دون استبدالها بقيم النشر المعتمدة. الأمر الحالي `npm run verify` يجمع lint وTypeScript والوحدات والبناء، ولا يشمل Playwright.

## 10. التوسع بعد هذه الدورة

هذه البنود مسار لاحق، ولا تدخل تنفيذ الإصلاحات أو تغيّر نطاق الموقع الحالي تلقائيًا.

- [ ] **F01 — حجز مواعيد:** بعد ظهور عبء فعلي في التنسيق اليدوي، اختيار وسيلة مواعيد بوقت ومنطقة زمنية واضحين وتأكيد/إلغاء. يحتاج تصميمًا مستقلًا ولا يُسمى زر واتساب الحالي حجز موعد مؤكدًا.
- [ ] **F02 — إدارة طلبات بسيطة:** بعد إثبات الحاجة التشغيلية، تحديد مالك البيانات والحد الأدنى من الحقول والصلاحيات ومدة الاحتفاظ قبل إضافة تخزين أو لوحة إدارة.
- [ ] **F03 — موارد للطلاب ثم منصة تعليمية:** يبدأ بموارد بسيطة إذا لزم، وتُبحث الحسابات والواجبات والمدفوعات فقط إذا بررتها احتياجات النشاط. أي تغيير في تخزين بيانات المتعلمين يمر بمراجعة أمن وخصوصية مستقلة.
